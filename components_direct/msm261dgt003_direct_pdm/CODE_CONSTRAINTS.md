# MSM261DGT003 麦克风驱动：约束补充说明

本文是代码生成、复用和审查时的约束清单。它描述当前接口能够保证的边界，不把应用层目标写成驱动能力。

## 1. 硬件和资源约束

- 目标器件为 MSM261DGT003 PDM 数字麦克风，模块供电为 3.3 V；必须共地。
- 当前 ESP32-WROOM 板卡绑定为 I2S0、PDM CLK GPIO18、PDM DATA GPIO2。
- GPIO18 同时登记为 SPI SCK。PDM 采集期间，SPI 不得占用 GPIO18；资源冲突由板级/组合层处理，不能由驱动静默抢占。
- GPIO2 是启动绑带相关引脚。修改接线或更换板卡后，必须重新验证冷启动和下载模式；不能因为一次启动成功就删除该风险。
- 模块 SW2 的 L/R 电平必须与 `Msm261dgt003DirectPdmConfig.channel` 一致。当前驱动没有读取芯片 ID 或读取 SW2 状态的接口。

## 2. 时钟和采样率约束

- 只接受 16,000～48,000 Hz 的 PCM 采样率。
- 由驱动选择的 PDM CLK 必须位于 1.1～4.0 MHz；超出范围时初始化失败。
- 当前实现只选择 64x 或 128x 降采样。不要在调用者中传入或假设其他降采样倍率。
- 数据手册的时钟占空比和实际声道边沿仍属于硬件时序验收项；代码编译通过不能替代示波器检查。

## 3. 生命周期、并发和缓冲区约束

- `Msm261dgt003DirectPdm` 由调用者拥有，建议声明为 `{0}`，并通过默认配置函数初始化配置。
- 一个实例的完整生命周期必须由同一任务拥有，或由应用层互斥锁保护。驱动和 BSP 不提供内部并发序列化。
- `read` 是同步调用。调用者提供的 `int16_t` 缓冲区必须在调用返回前保持有效；驱动不保存该指针，也不负责分配或释放缓冲区。
- `sample_capacity` 必须大于 0，且对应字节数不能溢出；`samples_read` 必须由调用者提供并检查。
- 所有读取必须使用有限 `timeout_ms`。BSP 上限为 60,000 ms；不得使用无限等待语义。
- 驱动没有 ISR 回调接口，不应在 ISR 中调用同步读取、停止或释放函数。

## 4. 分层边界

| 层 | 允许内容 | 禁止内容 |
|---|---|---|
| `bsp_i2s` | I2S0 channel、PDM RX、DMA、GPIO、超时读写、资源释放 | 麦克风型号语义、音量阈值、VAD、播放策略 |
| `msm261dgt003_direct_pdm` | 采样率/时钟约束、L/R 选择、生命周期封装、PCM 交付 | 固定板卡 GPIO、产品状态机、PDM 寄存器细节 |
| 最小例程 | 绑定板卡资源、调用生命周期、打印峰值/平均绝对值 | SPL 标定、录音存储、回放、AEC、业务阈值 |

## 5. 不得声称的能力

除非新增独立证据，不得从当前代码推导或宣传：

- 校准声压级、灵敏度、频响、失真、信噪比或录音音质；
- 人声识别、VAD、自动增益、滤波、回放或 AEC；
- 麦克风物理在线状态或芯片 ID 身份确认；
- 多实例并发安全；
- GPIO18 与 SPI 同时可用；
- 长时间稳定运行或量产音频就绪。

## 6. 修改和验收规则

修改采样率范围、PDM 时钟策略、slot 映射、DMA 行为或资源绑定时，必须同步检查 component、BSP、board、recipe、transport 和 validation Context。

验收应至少分层记录：

1. 编译：完整 example 配置、编译、链接和生成固件；
2. 波形：GPIO18 的 PDM CLK 频率/占空比，以及 GPIO2 的数据活动；
3. 运行：有限超时读取成功、样本数量合理、读错误可见；
4. 声学：安静与发声时峰值/平均绝对值出现可重复变化；
5. 风险：冷启动、下载模式、SPI 冲突和长时间运行分别记录。

当前 validation context 已记录编译、烧录和一次拍手响应证据，但音质、声学标定、长稳和 GPIO18/SPI 共存仍未验证。
