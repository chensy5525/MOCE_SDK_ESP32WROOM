# MAX98357A Flash MP3 播放实现说明

## 1. 代码用途

该示例验证经典 ESP32 直接从内部 Flash 播放 MP3，并通过 I2S0 驱动
MAX98357A 和单个扬声器。它不依赖 CH32，不包含麦克风，也不负责
Wi-Fi 闹钟调度、电机或舵机控制。

当前数据链如下：

```text
Flash FATFS /audio/test.mp3
    -> esp_audio_codec MP3 decoder
    -> signed 16-bit PCM
    -> stereo-to-mono downmix
    -> sample-rate conversion to 48 kHz
    -> master volume ramp and limiter
    -> duplicated left/right I2S slots
    -> I2S0 DMA
    -> MAX98357A
    -> one bridge-connected speaker
```

MP3 文件是本地测试资产，受 `.gitignore` 排除，不随源码提交。

## 2. 主要处理

### 2.1 Flash 文件系统和 MP3 解码

- `partitions.csv` 为只读测试音频预留 `0x270000` 字节 FATFS 分区。
- 示例挂载 `/audio`，打开 `/audio/test.mp3`，并检查文件长度。
- `audio_mp3` 封装 Espressif `esp_audio_codec` MP3 解码器。
- 输入使用固定 2048 字节缓冲，解码 PCM 使用固定 8192 字节缓冲；
  播放循环中不为每个音频块动态分配内存。
- 仅接受单声道或双声道 signed 16-bit PCM；不支持的格式返回错误。

### 2.2 双声道合并为单扬声器输出

双声道输入使用以下处理：

```c
const int32_t left = input[index * 2U];
const int32_t right = input[(index * 2U) + 1U];
const int16_t mono = (int16_t)((left + right) / 2);
frame.left = mono;
frame.right = mono;
```

- 使用 `int32_t` 计算 `left + right`，避免 16 位加法溢出。
- 左右声道取平均，避免单扬声器只播放一侧而丢失另一侧内容。
- 相同单声道样本复制到两个 I2S 时隙，因此不依赖功放选择左槽还是右槽。
- 下混发生在重采样之前，后续只处理两路相同的单声道数据。

### 2.3 重采样

- 解码器报告源采样率后初始化有状态线性重采样器。
- 当前 I2S 输出采样率固定为 48 kHz。
- 重采样状态跨输入块保留，避免每个 MP3/PCM 块边界重新起算造成时长漂移。
- 输出使用固定 512 帧缓冲。

如果产品阶段所有音频资产都预处理为同一受支持采样率，可以进一步取消
不必要的运行时重采样；当前版本保留它以兼容 44.1 kHz 和 48 kHz MP3。

### 2.4 音量、渐变和限幅

- 当前板级试听音量为 `1000 permille`，即软件满幅；硬件增益仍应从低档开始。
- 播放从零增益开始，在 4800 个 48 kHz 帧内渐强，时长为 100 ms。
- 混音器使用 Q16 定点增益，并在输出前饱和到 signed 16-bit。
- `limited_sample_count` 记录数字限幅事件，便于区分数字削顶和功放/扬声器失真。

MAX98357A 自身没有软件音量寄存器；播放音量由 PCM 数字增益与硬件
`GAIN_SLOT` 共同决定。100% 是当前用户指定的试听设置，不自动代表最终产品
的安全默认音量。最终值仍需结合扬声器阻抗、额定功率、功放增益和温升确定。

### 2.5 I2S 和清理

- I2S0 使用 standard TX：BCLK GPIO18、LRCLK GPIO19、DIN GPIO2。
- `max98357a_direct` 只负责 I2S 初始化、启动、带超时 PCM 写入和释放；
  它不包含 MP3、文件系统或产品控制策略。
- 所有初始化步骤检查 `esp_err_t`；失败路径按已成功初始化的资源逆序释放。
- 当前示例上电只播放一次，播放完成后释放功放、解码器、文件和 FATFS。

## 3. 相对之前版本的区别

| 项目 | 之前版本 | 当前版本 |
|---|---|---|
| 双声道处理 | 左右声道保持独立 | `(L + R) / 2` 下混后复制到两个 I2S 时隙 |
| 单扬声器内容 | 取决于 MAX98357A 选择的声道 | 左右内容均保留，不依赖槽位选择 |
| 中间加法位宽 | 没有左右相加 | 使用 32 位中间值避免溢出 |
| 软件音量 | 150 permille（15%） | 1000 permille（100%） |
| 渐强 | 100 ms | 保持 100 ms |
| 数字限幅统计 | 已有 | 保留，并用于满音量验证 |
| MP3 测试资产 | 早期本地歌曲 | 可替换的本地 `test.mp3`，仍不提交 Git |
| 电机/Wi-Fi | 未集成 | 本次没有修改其架构或代码 |

## 4. 已完成验证

### 4.1 构建

- ESP-IDF：6.0.2。
- Target：classic `esp32`。
- 构建结果：通过。
- 应用镜像：`0x44020` 字节。
- 最小应用分区：`0x180000` 字节，构建报告剩余 82%。

### 4.2 烧录和硬件

- 目标：ESP32-D0WD-V3 revision 3.1，COM6。
- bootloader、分区表、应用和音频 FATFS 均通过 esptool 写后哈希校验。
- 单扬声器已实际出声。
- 用户实听确认早期测试音频静音段无明显底噪、启动/结束无明显爆音，
  当时音量下无明显失真。

### 4.3 满音量软件验证

本地测试资产（不提交）：

- SHA-256：`6410FD978D57632F5C8C383EA7EBD65BD8E1F9CB893E381717482EB95A81C0D0`。
- 完成输出：1,449,263 帧，约 30.2 秒。

以上证明当前文件在 100% 数字音量下没有触发软件限幅，但不能替代对模拟输出、

## 5. 已知限制和后续集成边界

- 当前是一次性板级播放示例，不是最终小车 `audio_service`。
- 尚未接入 Wi-Fi 闹钟的 `PLAY`/`STOP` 命令队列。
- 目前只有启动渐强；产品 STOP 命令需要在继续输出 PCM 时渐弱到零，再停止 I2S。
- 尚未验证 Wi-Fi、MP3 解码和运动控制同时运行时的任务优先级、栈余量、
  I2S 欠载、看门狗和 Flash 访问延迟。
- 尚未完成电机、舵机动作时的供电噪声、地弹和音频串扰测试。
- 100% 数字音量的实听失真和扬声器温升仍需用户确认；`limiter events: 0`
  只表示数字端没有削顶。
- 当前 4 MiB 分区没有 OTA 槽，不能把该测试分区方案直接视为最终产品发布布局。
